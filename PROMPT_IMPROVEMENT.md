## Trading Fluppy ENGINE + VISUAL (парная связка)

> **Назначение файла.** Полноценный профессиональный промт, описывающий поэтапное
> улучшение двух исходников на PineScript v6:
> - `Script_Latest_V1_Engine.txt` (≈ 5660 строк) — индикатор-«двигатель» (математика, скоринг, зоны, симулятор сделок, экспорт каналов)
> - `Script_Latest_V1_Visual.txt` (≈ 1410 строк) — визуальный индикатор-компаньон (рендер зон, метки входа/выхода, дашборд)

> Промт составлен после глубокого анализа обоих файлов. Он структурирован по

> создания файла — сразу применить улучшения).

## 0. КРАТКИЙ РЕЗУЛЬТАТ АНАЛИЗА (база для требований)

### 0.1. Архитектура связки
- **ENGINE** — `indicator(overlay=true)`, **9 БЛОКОВ**: константы → 200+ inputs →
  динамический MTF-движок → сессии/макро-объём → математика и SMC-pivots →
  типы и методы (зона как UDT с ~25 полями + bit-pack meta) → 9-компонентный
  скоринг → менеджер зон → исполнение/риск/симулятор → экспорт.
- **VISUAL** — `indicator(overlay=true)`, читает ENGINE через ~40 каналов
  `input.source()`, имеет **fallback-вычисления** при отключённом ENGINE,
  отрисовывает 4 зоны (Sup1/Sup2/Res1/Res2), сессии, PD-полосу, дашборд
  на 44 строки и метки входа/выхода через **state-machine на 11 состояний**.
- **Протокол**: ENGINE публикует версию `287.0` через первый plot;
  VISUAL хранит `EXPECTED_ENG_VERSION = 287.0`, `LEGACY_ENG_VERSION = 286.0`.
  Жёсткое ограничение TradingView — **64 output-слота на индикатор**, ENGINE
  использует ровно 64 (63 невидимых канала данных + 1 видимый VWAP).

### 0.2. Bit-pack `meta`-канала зоны
4 канала `Sup1/Sup2/Res1/Res2 Meta` экспортируют:
`ztype` (один из 9: OB/BB/RZ/IMB/ACC/DST/VCP/MBR/PROP/MITIG) + `tier` (BEST/STRONG/NORMAL/PIVOT) +
`score` (0-150) + `is_propulsion` + `is_bull`. VISUAL декодирует через `f_decode_zone_meta()`.

### 0.3. Симулятор сделок (sim_*)
В ENGINE крутится симулятор позиций: `sim_in_position`, `sim_direction`,
`sim_entry_price`, `sim_sl_price`, `sim_tp1_price`, `sim_tp2_price`. Выходы
по SL/TP1/TP2/BOS пишутся в `sim_trades/sim_wins/sim_gross_profit/sim_gross_loss/sim_equity`
и экспортируются. Гейты входа: `inp_min_rr` (≥ 1.5 R:R) и `_trend_penalty`
(контр-трендовый вход требует +1 conflu).

### 0.4. State-machine подсказок в VISUAL (11 состояний)
`WAIT → ZONE_DETECTED → ZONE_TOUCH → ENTRY_LONG/SHORT → IN_LONG/SHORT →
PARTIAL_TP1 → EXIT → cooldown → WAIT`. Confluence-счётчик из 6 факторов
(trend, VWAP, bull/bear close, engulfing, SFP, BOS). Жёсткие переходы
гейтятся `barstate.isconfirmed`.

### 0.5. Подтверждённые **жёсткие инварианты**, которые НЕЛЬЗЯ нарушать
1. Количество plot-слотов в ENGINE ≤ 64 (сейчас 64).
2. **Порядок** `plot()` в ENGINE = порядок `input.source()` в VISUAL.
3. Любое изменение количества/порядка каналов = bump `EXPECTED_ENG_VERSION` +
   обновление `LEGACY_ENG_VERSION = <предыдущая>`.
4. Хинт-state-machine VISUAL должна выходить из позиции **только** по транзиции
   `sim_in_position` ENGINE-а (исторический баг V277). Никаких независимых
   условий выхода в VISUAL при подключённом ENGINE.
5. Реальное время: сигналы для подсказок (BOS/CHoCH) уже **не гейтятся**
   `barstate.isconfirmed`, гейтятся только переходы state-machine.
6. Нельзя удалять переменные/функции, на которые есть ссылки даже в редко
   достижимых ветках (`debug_mode`, neural-сетка, scoring loop).

### 0.6. Кандидаты «мусора», которые на поверку НЕ мусор
> **Внимание!** Поверхностный анализ ошибочно считает мусором:
> `f_remove_old_rejected` (вызывается строкой 4725), `zone_deltas`/`zone_vol_deltas`
> (используются скорингом 1961-2012, заполняются 4344-4462),
> `global_origin_state` (читается 1987/4340/4452, пишется 4351/4463),
> `rejected_db` (наполняется и используется в debug). Перед удалением
> ОБЯЗАТЕЛЕН `grep` всех ссылок.

## 1. ЦЕЛИ УЛУЧШЕНИЯ

1. **Логика**: повысить корректность и читаемость PineScript v6 кода без
   изменения торгового поведения симулятора.
2. **Чистка мусора**: только то, что подтверждено как неиспользуемое —
   комментарии-«артефакты», магические числа, дубли вычислений, осиротевшие
   ветки. Строгое правило: «при сомнении — оставить».
3. **Визуал**: зоны должны быть мгновенно понятны пользователю
   (тип, сила, направление). Метки входа/выхода — привязаны к зонам
   (зона-эмодзи, тип, score), показывают R:R, SL/TP1/TP2, P&L, причину.
4. **Конфигурируемость**: магические числа state-machine VISUAL вынести
   в `input.*`, чтобы трейдер мог тонко настраивать поведение без правки кода.
5. **Версионирование**: после изменения протокола экспорта или семантики
   данных — bump `ENGINE_VERSION` и синхронизация в VISUAL.

## 2. ОГРАНИЧЕНИЯ TRADINGVIEW (ПЛАТНЫХ ПОДПИСОК НЕТ)

- Лимит **64 output-слота на индикатор** (plot/plotshape/plotchar/plotarrow/
  plotbar/plotcandle/bgcolor/barcolor/fill).
- Лимит box/line/label — **500 объектов каждого типа** (`max_boxes_count=500`,
  `max_lines_count=500`, `max_labels_count=500`).
- `max_bars_back` рекомендуемо ≤ 5000 (ENGINE уже имеет защиту).
- `request.security` с `lookahead_on` создаёт future-bias на исторических барах —
  допустимо ТОЛЬКО для daily-anchored данных (PD-зоны).
- Никаких внешних библиотек / repaint-агрессивных конструкций.
- Pine v6: строгая типизация, `nz()` обязателен для float/int с возможным `na`.

## 5. ВИЗУАЛЬНЫЕ УЛУЧШЕНИЯ

### 5.1. Зоны (читаемость)
- 5.1.1. **Tag-метка типа зоны** внутри бокса. Используется встроенный
  параметр `box.text` (а **не** отдельный `label.new()`) — это **не расходует**
  объекты из лимита 500 label/box/line. Текст вида `"🛡️ BB · 92"` (эмодзи
  зоны + тип + score). Тип берётся из decoded meta. Применяется ко всем
  4 рендерящимся зонам (Sup1/Sup2/Res1/Res2).
- 5.1.2. **Адаптация прозрачности к теме графика**. Добавить
  `chart_theme_v = input.string("Auto", "Тема графика", options=["Auto","Light","Dark"])`.
  Для **Dark** — диапазон **80→20** (зоны заметнее на тёмном фоне). Для
  **Light/Auto** — диапазон **95→40** (исторически безопасный, не ломает
  существующие настройки). Реализуется через расширенный
  `f_score_to_transp_v(score, theme)`.
- 5.1.3. **Динамический glow-offset**. Текущий `(top-bot)*0.05` для маленьких
  зон даёт неразличимый glow. Заменить на
  `math.max(syminfo.mintick * 4, (top - bot) * 0.05)`.
- 5.1.4. **Цвет границы Sup2/Res2** оставить чуть темнее (контрастность с Top1).

### 5.2. Подсказки входа/выхода (привязка к зонам)
- 5.2.1. Метка входа должна **обязательно** содержать:
  - Эмодзи зоны (`f_zone_emoji(hint_zone_type)`).
  - Тип зоны строкой (`OB/BB/RZ/IMB/...`).
  - Tier (BEST/STRONG/NORMAL/PIVOT) и score.
  - R:R (TP1 / TP2).
  - SL / TP1 / TP2 цены.
  - Reason входа.
  → Уже реализовано (V287); сохранить структуру, но добавить
  **компактный режим** для младших ТФ.
- 5.2.2. **Компактный режим**. `input.bool(false, "Компактные метки (1 строка)")`.

- 5.2.3. Выход:

## 9. ПРОДВИНУТЫЕ МЕТОДЫ АНАЛИЗА ГРАФИКОВ (V287.2)

> Этот раздел добавлен после первой итерации улучшений. Все техники реализованы
> **локально в VISUAL** (на доступных каналах OHLC + ATR + сессии + ENGINE-данные)
> и **не требуют изменения протокола** — `EXPECTED_ENG_VERSION` остаётся 287.0.

### 9.1. Цель
Дать пользователю набор институциональных техник анализа (ICT / SMC / PA),
которые повышают качество входов и помогают избегать «ловушек ликвидности».

### 9.2. Ограничения
- Не плодить exports в ENGINE — лимит 64 plot-слота.
- Каждая техника — **opt-in** через `input.bool(...)`, чтобы пользователь
  включал только нужное.
- Кэшировать swing-pivots в `var array<>` буфере фиксированного размера (≤5),
  чтобы не утекать в `max_bars_back`.
- Объекты `line`/`box`/`label` создаются с `var` и переиспользуются (delete
  старого → create нового), чтобы оставаться в лимитах 500.

### 9.3. Список техник

#### 9.3.1. Equal Highs / Equal Lows (EQH/EQL) — пулы ликвидности (ICT)
- **Идея**: два соседних swing-pivot с почти равной ценой → над ними копится
  buy-stop / под ними — sell-stop ликвидность. Цена статистически часто их
  «посещает» перед разворотом.
- **Параметры**: `eql_eqh_pivot_len` (left/right для `ta.pivothigh/pivotlow`),
  `eql_eqh_tol_atr` (допуск равенства в ×ATR), `eql_eqh_lookback`
  (макс. дистанция между парой пивотов в барах).
- **Визуал**: горизонтальная dashed-линия от пивота до пивота с продлением
  вправо + лейбл `💧 EQH` / `💧 EQL`.
- **Алерты**: `EQH Liquidity Hit` / `EQL Liquidity Hit`.

#### 9.3.2. Liquidity Sweep markers (stop hunt)
- **Идея**: фитиль текущего бара пробивает последний `sweep_pivot_len`-pivot,
  но close — внутри (классический stop hunt / SFP). Контртренд-триггер.
- **Визуал**: `plotshape` ▼ над баром (sweep high) или ▲ под баром (sweep low),
  с эмодзи 🎯.
- **Алерты**: `Liquidity Sweep High/Low`.

#### 9.3.3. Optimal Trade Entry (OTE) zone
- **Идея ICT**: после импульса цена ретрейсит в Fib 0.618–0.786 — это «золотая
  зона» с наилучшим R:R и минимальным SL.
- **Параметры**: `ote_swing_lookback`, `ote_fib_low` (0.618), `ote_fib_high`
  (0.786). Направление импульса определяется по позиции `highestbars`/`lowestbars`.
- **Визуал**: dotted-box зелёного (для bull-leg) / красного (для bear-leg)
  цвета с подписью `OTE LONG (0.618–0.786)`.
- **По умолчанию OFF** — это «сильная» техника, лучше включать только в режиме
  trending (regime 0/1).

#### 9.3.4. Killzone-бейдж в entry-метках
- **Идея**: в ICT торговля идёт почти исключительно в килзонах
  (London 03:00–11:30 NY, NY 09:30–16:00 NY, Overlap 09:30–11:30, Asia 19:00–03:00).
  Знание времени дня — критично.
- **Реализация**: к тексту entry-метки (long и short, full и compact) приклеивается
  `\n🌐 LDN×NY Overlap` / `\n🗽 NY Killzone` / `\n🇬🇧 London Killzone` / `\n🗾 Asia Killzone`
  / `\n💤 Quiet`.
- **Затраты**: 0 объектов (это просто строка).

#### 9.3.5. Trend Strength meter (sparkline 0–8)
- **Идея**: один взгляд — и видно общую силу текущего тренда. Композитный
  индекс из 5 компонент:
  - HTF тренд (0/1)
  - Согласованность HTF↔ITF (0/1)
  - Расстояние от VWAP в ATR (0/1/2 — пороги 0.5, 1.5)
  - |Z-Score| (0/1/2 — пороги 1.0, 2.0)
  - Regime != Range и != Volatile (0/1)
- **Визуал**: строка дашборда `Trend Strength` с sparkline `▁▂▃▄▅▆▇█` и числом
  `n/8`. Цвет: lime ≥6, yellow ≥4, orange ≥2, gray <2.

#### 9.3.6. Power of 3 (AMD) — фаза дневного цикла ICT
- **Идея**: каждый торговый день делится на три фазы:
  - **Accumulation** (Asia): узкий range, накопление позиций.
  - **Manipulation** (London open): ложный пробой за Asia high/low (ловушка).
  - **Distribution** (NY): экспансия в направлении истинного движения.
- **Реализация (упрощённая, без daily-данных)**: эвристика по килзонам:
  - В Asia → Accumulation;
  - В London без overlap → Manipulation;
  - В Overlap → переходная фаза;
  - В NY → Distribution;
  - Иначе → Off-cycle.
- **Визуал**: строка дашборда `Power of 3 (AMD)` с эмодзи и цветом фазы.
